# Flutter-клієнт TaskFlow

## Поточний стан

У `frontend/` створено Flutter-застосунок для Android та iOS. Зараз реалізовано реєстрацію, вхід, вихід, захищене зберігання JWT, список дощок і перегляд колонок та карток на дошці. Дії редагування, коментарі, учасники та SignalR ще не підключені.

## Структура

```text
lib/
  app/                    # MaterialApp, маршрути, перевірка сесії
  core/
    auth/                 # TokenStorage і єдиний SessionStore
    config/               # адреса API через --dart-define
    network/              # Dio, Bearer-заголовок, помилки
  features/
    auth/
      data/               # AuthRepository
      presentation/       # форма входу та AuthActions
    boards/
      data/               # моделі відповіді й BoardsRepository
      presentation/       # список і деталі дошки
```

Екран читає стан через Riverpod; репозиторій викликає API через спільний Dio-клієнт. `SessionStore` один раз відновлює JWT зі сховища при запуску й є єдиним місцем для входу та виходу. `AuthRepository` повертає токен після входу, `AuthActions` передає його в `SessionStore`, а Dio бере токен із поточного стану сесії. Віджети не формують HTTP-запити й не зберігають токен. JSON-моделі відповідають фактичному формату бекенду; окремий доменний шар додається лише для складної логіки.

## Підключення до API

Адреса API задається на етапі запуску:

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:5079/api/
```

Це значення вже є типовим для Android-емулятора. Для іншого пристрою передайте доступну йому адресу. `localhost` на фізичному телефоні означає сам телефон, а не комп’ютер розробника. Для iOS і production використовуйте HTTPS з довіреним сертифікатом.

JWT зберігається через `flutter_secure_storage` і додається до запитів як `Authorization: Bearer ...`. Бекенд видає токен на дві години та поки не має refresh endpoint. При `401` на читанні дощок клієнт очищує локальну сесію та повертає форму входу.

## Наступні функції

1. Створення й редагування дошок, колонок і карток.
2. Учасники, ролі, виконавці, коментарі та журнал активності.
3. Переміщення карток після уточнення серверного порядку `Order`.
4. SignalR з повторним входом у групу дошки після перепідключення.
5. Тести для авторизації, прав доступу й сценаріїв двох користувачів.
